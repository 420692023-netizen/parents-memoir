# 老照片分支：照片入传五步流程（photo-archive）

> ★ 定位一句话：**本分支不做"图片管理"（认人/去重/建索引，相册软件已做烂），做的是"照片入传"——把照片变成人物库条目、时间线节点和成书插页。**
> 实测背书：某批老相册实测——23 张图（含 14 个 AI 加工副本）自动配对归并为 16 张独立原件，12 张相册照片 11 张人物实名，整本相册拍摄窗口凭"人物生年＋花期"收敛为传主生命最后两年。

## 〇、能力边界（先说清楚，再动手）

- ✅ **可直接承诺**：读图描述、背面题字转写、年代推断（有硬依据时）、跨照片关联归组、原件↔AI 副本配对、挂接人物库与家书链
- ⚠️ **只做提示**：人物指认一律以 `[?]` 候选输出，**裁决权归委托人**（与手写分支"AI 是提示器不是裁判"同构）；"这几张可能是同一人"仅作相似度提示，不得宣称"AI 人脸识别认定"
- ❌ **绝不承诺**：凭脸直接认定姓名；从模糊老照片"还原"真实面容（AI 重建的面容**不是本人**，必须显式标注）

## 一、目录规范（委托人档案侧）

照片及视频**单独存放** `素材库\照片\`，**不与信件扫描混放**。批次制：

```
素材库\照片\
├── 照片NN_描述_来源_原件.jpg     ← 平铺命名（早期批次）
├── _人物登记册.md               ← ★已确认人物总册（问一次、终身免问，见 §五）
└── <批次名>\                     ← 每批一个子目录，如 2023翻拍_老屋与母亲\
    ├── 01_原件翻拍\              ← 原件（保留原文件名，可追溯）
    ├── 02_AI加工版\              ← 上色/修复/增强副本
    ├── 03_动态视频\              ← AI 动态化视频
    ├── 04_待辨认裁片\            ← 从相册整页裁出的单张（供委托人辨认）
    ├── 05_AI动态还原_<日期>\     ← AI 精修+动态化产物（须配 _README 说明）
    ├── 06_人物头像\              ← ★人物头像裁片（供待认卡片与登记册引用）
    └── _原名对照_<批次>.md       ← 逐文件：描述/人物/定年/原件对照
```

**硬规矩**：E 盘等外部原件**只复制、不移动**；原文件名一律保留；AI 产物与原件分目录，不得覆盖原件。

## 二、入传五步流程

### ① 清点
跑 `python scripts/asset_inventory.py <照片目录> --photos`，生成**照片登记表**：每文件标 类型（原件/AI副本/视频）、AI 副本自动配对到原件、dHash 查重复（重复扫描件/重复上传会被点名）。**空目录扫描必须报错退出（fail loud），不得静默出空表。**

### ② 配对与去重（双哈希两级，借鉴 photo-content-recognition-curation-expert 的分层思路）

- AI 副本按文件名关键词（topaz/grok/上色/修图/enhance/denoise/faceai/remini 等）+ 前缀匹配自动挂到原件；名字配不上的用 dHash/pHash 内容级兜底（≤16 标注"内容匹配"，仍须人工确认）；
- **两级检测**（纯 Pillow 实现，不引入 torch 系重依赖）：

| 级 | 判定 | 含义 | 处理 |
|---|---|---|---|
| 疑似重复 | dHash 或 pHash 距离 ≤5 | 同一画面的重复扫描/重复上传 | 每组保留最清晰一张（原件优先），**删除须委托人确认** |
| 相似组 | pHash 距离 6–10 | 重拍/裁剪/上色/不同尺寸版本 | **仅提示不是结论**；已配对的 AI 副本不用再理；组内全是原件疑为连拍，请委托人挑保留张 |

- 相似对经**并查集**归并成组（链式相似——A≈B、B≈C——归为一组，避免漏报）；
- **先报告、后处理**（实测中"多扫描了一页被当成缺第 3 页"的教训：整理者的计数错误会凭空制造待办，去重能提前暴露这类结构错误）；
- 更深层（重裁剪/翻拍屏摄）超出经典哈希能力，交给第③步读图判读，不硬凑算法。

### ③ 逐张判读（读图）
每张记录：**画面描述 → 背面题字（有则按手写分支转写）→ 年代特征（见 §三）→ 背景场景 → 人物候选 `[?]`**。整页翻拍（相册页）含多张照片时，用 Pillow 裁出单张（存 `04_待辨认裁片\`），**裁片先自读验证位置再交委托人**——裁错页、切半人是常见事故。

### ④ 人物锚定（★优先级从高到低，前两级是本 skill 的独家优势；★先读人物登记册，见 §五）

**首轮先查册**：`_人物登记册.md` 已有的人物**自动挂名**（标注"据登记册"），**勿重复询问**；
仅新面孔或对不上号者，裁头像（存 `06_人物头像\`）生成待认卡片询问。AI 首轮"认识"的
只能是登记册里已有的人——对新面孔 AI 永远不认识，只能提示候选。

| 级 | 锚定手段 | 可靠度 |
|---|---|---|
| 1 | **照片背面题字**（按手写分支转写，注明书写者） | ★★★★★ |
| 2 | **家书文字定人**：信件中提及的人物/事件与照片互证（如某封信对位出"某小名"＝某正字人名） | ★★★★★ |
| 3 | **同批关联**：同底色/同取景点/同衣着出现在已确认照片中 | ★★★☆ |
| 4 | **硬时间锚反推**：某人出生年/事件年框定照片窗口（如彦宁 1987 春生 → 抱她的照片≥1988） | ★★★☆ |
| 5 | **面容相似**（与已确认照片比对） | ★ 仅提示 `[?]`，必须委托人确认 |

**定年优先用"硬锚"（题字日期＞人物生年＋体型＞物件年代＞花期），多锚交叉时以最硬的为准；冲突时并列保留，请委托人裁决。**

### ⑤ 裁决与入传
委托人逐条裁决后：人物写入**人物库**（人名正字总表/人物关系档，带照片实证标注）、照片写入**照片档案**（`素材库/照片档案_<主题>.md`），成书时进「老照片插页＋图注」。**图注一句话原则**：图注必须能独立唤起一段记忆（"母亲手植的喇叭花前，她抱着拾来的彦宁"），写不出就回去补访谈，不硬写。

## 三、年代特征速查表（中国家庭，1940s–1990s）

| 特征 | 断代指向 |
|---|---|
| 花边/浪边相纸 | 1970s–80s 国产相纸典型工艺 |
| 手工上色 | 1950s–70s 照相馆工艺 |
| 照相馆钢印/底边馆名 | 1950s–80s，且可定位城镇 |
| 中堂画＋条案＋木椅堂屋 | 传统农家布局，贯穿 1950s–80s |
| 小黑白电视＋台扇＋暖水瓶 | 1980s 中后期农家"三大件" |
| 军便装/中山装 → 的确良衬衫 → 西装 | 1960s–70s → 1980s 初 → 1980s 中后 |
| **植物花期**（本库实证两则） | 蔷薇类 4–5 月；凤仙/喇叭花类 6–10 月——**花盛开的户外照可锁定季节** |
| 相册：深蓝绒面自粘相册、塑膜翘裂 | 1980s 流行款 |

⚠️ AI 上色/修复版的**颜色不可作断代或花种依据**（色相系模型推测）。花种等具体物象**以委托人口述为准**（本项目实证：AI 三易其稿——蔷薇→凤仙→委托人一句"喇叭花"定案）。

## 四、AI 还原三条红线（写入所有 AI 加工产物的 README）

1. **面容红线**：精修/上色/动态化中的人物面容系 AI 重建，**不得声称是本人影像**；文件名与 README 都要标注（例：`母亲抱彦宁_精修上色_AI还原_面容非本人.png`）。
2. **用途红线**：AI 产物仅作展览/纪念，**不得当作史实影像**；入传必须标注"AI 还原"。
3. **原件红线**：AI 产物存独立目录（`02_AI加工版` / `05_AI动态还原_<日期>`），原件目录原封不动；README 记录"待重跑提示词"以便断点续作。

**修复工具推荐（不进本 skill 代码，引导用户自选）**：通用超分 Real-ESRGAN；人脸修复 GFPGAN / CodeFormer（档案用途建议 fidelity 权重 0.5–0.7，宁糊勿换脸）；上色 DeOldify / DDColor。重度照片库用户可推荐自托管相册平台 Immich（人脸识别＋CLIP 搜索），本 skill 只管建档与红线，不重造仓库层。

## 五、人物登记册（问一次、终身免问）

> 机制：把"每张照片反复问人"变成"每位新人只问一次"。登记册是照片线的
> 长期记忆，跨批次、跨会话生效——存放在照片根目录 `_人物登记册.md`。

### 5.1 格式（`asset_inventory.py --photos` 可自动读取并输出骨架）

```markdown
# 人物登记册（问一次、终身免问）

| 人物 | 首认照片 | 头像裁片 | 确认日期 | 备注 |
|---|---|---|---|---|
| 沈彦宁 | 01_原件翻拍/IMG_xxx.jpg（C组·母亲怀抱） | 06_人物头像/彦宁.jpg | 某日 | 某年夏收养 |
```

### 5.2 首轮建册流程（无册时）

1. **裁头像**：每张出现人物的照片，裁出人物头像存 `06_人物头像\`（整页相册先裁单张再裁头像，**裁片先自读验证**）；
2. **归簇**：按衣着/场景/相似度把"可能是同一人"的头像归组——**只作提示**；
3. **待认卡片**：每组一张卡（头像＋出现在哪几张＋上下文线索如"1988 年夏·老屋花丛前"），**一次性**列给委托人辨认（不要一张一问地反复打扰）；
4. **入册**：委托人答复逐行写入登记册（人名／首认照片／裁片路径／确认日期／备注）；
5. **生效**：此后任何批次先读册——已入册者自动挂名。

### 5.3 两条红线（写死，防错挂传染）

1. **AI 首轮"认识"的只能是登记册里已有的人**。对新面孔，AI 永远"不认识"——它没有可靠的人脸识别能力（老照片尤甚），只能给出"可能与登记册中某人是同一人"的候选提示 `[?]`，**第一次仍须委托人亲认**，认了才入册。
2. **挂名带置信度，矛盾降级**。已入册者再出现自动挂名；但相似度低或场景矛盾（如"彦宁"出现在其出生前的照片）时，**照样降级 `[?]` 询问**——防止一次错挂顺着登记册传染全库。
