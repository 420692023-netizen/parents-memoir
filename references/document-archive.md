# 文档分支：素材文档查重与人物扫描（document-archive）

> ★ 定位一句话：**不做"文档管理"（自动摘要/自动归类/知识库，通用工具已做烂），做的是"素材文档入传前体检"——把重复副本点名、把每个人物提及提示出来，裁决权归委托人。**
> 实测背书：某项目全库实测——267 个文档（md/txt/docx）扫出 **4 组精确重复**（同一盲读稿在两个目录双胞胎并存、同一封信五份副本）＋误转形警示命中真校对点（某封信转写稿"某误字"疑为"某正字"之误转）。

## 〇、能力边界（先说清楚，再动手）

- ✅ **可直接承诺**：文件级精确查重（SHA-256）、跨格式同文检测（去空白比对，.txt/.md/.docx）、人物提及扫描（对照登记册与正字总表）、误转形警示
- ⚠️ **只做提示**：人名提及≠同一人（重名风险，如「张三」与「李四」）；误转形只给更正方向，**原话照录区不改字**
- ❌ **不承诺**：.doc/.pdf/.wps 内容解析（标"待人工"，不硬解析）；版本演进稿的模糊相似比对（那属人工审读，不越界）；自动摘要、自动建档

## 一、什么时候用

用户给来一个素材目录说"帮我整理/查重/看看里面有什么"，目录里是混合文档（txt 转写稿、md 补记、docx 成稿、pdf 扫描件）时，第一步先跑体检：

```bash
python scripts/asset_inventory.py <目录> --docs [--out 文档登记表.md]
```

空目录**必须报错退出（fail loud）**，不得静默出空表。与照片分支互不替代：照片走 `--photos`，文档走 `--docs`，混合目录各跑一遍。

## 二、登记表四节怎么读

| 节 | 内容 | 处理原则 |
|---|---|---|
| 〇 人名来源 | 脚本自动向上/向下找到 `_人物登记册.md` 与 `人名正字总表.md` | 找不到时仅出查重结果，不硬猜人名 |
| 一 精确重复 | SHA-256 完全一致的文件组 | **只报告不删除**；保留哪份（通常留路径最规范的一份）委托人确认。实测教训：重复副本会让人误判"缺文件/多文件"（"多扫描一页被当成缺第 3 页"），查重先行可暴露结构错误 |
| 二 内容重复 | 去空白后一致、但文件哈希不同（同文异名/跨格式） | 属**同一内容的多份载体**，不是两个文档；请委托人指定正本，其余归档 |
| 三 人物提及 | 逐文件列出命中人名（次数）＋误转形警示 `[?]` | 见下方红线；按命中总量排序，高密度文件优先人工过目 |
| 四 文档清单 | 全部文档：可读/待人工/大小/提及数 | "待人工"＝.doc/.pdf/.wps，不硬解析 |

## 三、人物提及扫描的红线（写死，防错挂传染）

1. **提及≠认定**。命中只说明"该文件里出现过这个名字"，不代表就是本家同一位人物——同名不同人是常态（例如：张三〔小学老师〕与李四〔委托人〕）。报告中一律以 `[?]` 级别提示。
2. **称谓不作别名提示**。称谓随家族史实变人——「大舅」在某日之前指一位长辈、之后指另一位长辈；若提示「『大舅』疑为『张三』之误转」，等于把称谓时间轴踩平。脚本已内置称谓黑名单（大舅/二舅/奶奶/外婆类），**任何人工解读同样禁止**。
3. **误转形只提示方向，不改字**。「『张山』疑为『张三』之误转」只是线索；**原话照录区一字不改**，正字替换只发生在整理者正文/表格/台账（与人名正字总表执行口径一致）。
4. **正字总表的解析边界**。脚本只认表头严格为"正字"的列；"正字情况"等**待核台账表整表跳过**——里面的存疑名（〔考?〕标记）本就不该入检索。废用名（~~删除线~~）不入检索、不作提示。
5. **自吞防护**。本脚本生成的"文档登记表*.md"会在下次扫描时被跳过，防止报告被当素材。

## 四、项目配置模板（`素材库/项目配置.md`）

> v6 起，字辈模板／写信人映射／已校正清单**全部外置**到这一份文件——
> 一份文件同时做到三件事：发布包零真实数据、委托人的项目功能不损失、换项目只改一处。
> **三段各自独立：缺哪段就关掉对应功能，绝不报错。**

```markdown
## 字辈模板
（每行一条正则，. 代表任意一字。用于自动抓「不符合字辈的疑似误字」）
某.某
某某.

## 写信人
（格式：人名 = 关系。人名出现在文件名里即判定该写信人，决定排序权重）
某某某 = 母亲
某某某 = 父亲
某某某 = 委托人

## 已校正
（格式：信件编号 [备注]。已入库的信不再进优先校正队列）
信-000 已校正入库
```

> ★**这三段内容必须由委托人自己填**：字辈与亲属称谓是家族内部规则，
> AI 无从推断，开发者也不能包办（各家字辈不同）。
> 填好后 `person_density.py` 与 `list_photos.py` 自动读取，无需改脚本或传命令行参数。

## 五、与照片分支的分工

| | 照片（--photos） | 文档（--docs） |
|---|---|---|
| 查重对象 | 画面（dHash/pHash 感知哈希） | 文件字节（SHA-256）＋文本内容（去空白） |
| 人物机制 | 登记册＋头像待认卡片（问一次终身免问） | 正字总表＋登记册纯文本匹配（无头像环节） |
| 产物 | 照片登记表 → 照片档案 | 文档登记表 → 人工取舍 |

两边共享同一条铁律：**AI 是提示器，不是裁判；重复项与误转形的处理权都在委托人。**
